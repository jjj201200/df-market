# 文档落盘前增量一致性快检（通用方法论）

在把修订写入 CLAUDE.md / 指南手册 / memory / SKILL.md 之前，快速核对本次涉及条目与代码现状的一致性。本 skill 只管**本次变更涉及的文档范围**，不做全量扫描——全量由 `skill-doc-audit` 及其项目定制版承担。

## 辅助文件

- `references/check-catalog.md` —— 四项核查清单 + 索引完整性五步闭环 + 工具选择（**索引完整性强制步骤不得降级为抽样**）

## 核心原则

- **增量、轻量、守门**：只核查本次待落盘的文档及其触及的条目
- **默认阻断**：发现任一不一致即中止落盘，交由主进程决定如何处理
- **只读**：仅 Read/Grep/Glob/LSP；禁止任何修改
- **快**：单次调用期望在数十秒内出结果，不引入重型 subagent 切分（那是全量审计的事）

## 触发条件（通用）

主调方（通常是项目的"任务回顾 / retrospective" skill）判断本轮建议将**修改**以下任意类型的文件时，必须在落盘前调用本 skill：

- 项目根规范（`CLAUDE.md`、`AGENTS.md`、`GEMINI.md` 等）
- 手册目录（`CLAUDE_DOCS/`、`docs/`、`documentation/` 下的指南）
- 子项目/子模块规范
- 外部 memory 文件及其索引

> **SKILL.md 快检请用 `skill-sync-check`**。skill 变更的级联检查（触发词、description、交叉引用、职责边界）与文档不同，不在本 skill 范围。

## 输入

主调方必须提供：

1. **待修改文件清单**：每份文件的绝对路径
2. **变更明细**：每份文件的新增/修改/删除条目（摘要即可，具体 diff 由本 skill 读文件比对）

不要直接把 diff 塞进 prompt——让本 skill 自己 Read 对比。

## 核查执行

Read `references/check-catalog.md`，按其「1. 每份文档的四项核查」与「2. 索引完整性强制步骤」执行。

## 输出格式

两种结果之一：

### 通过
```
✅ 快检通过

覆盖文件：
- [文件 1]（新增 N 条、修改 M 条）
- [文件 2]（...）

已验证引用数：X
无一致性问题。
```

### 阻断
```
❌ 快检阻断 — 发现 N 处不一致

### [文件路径]

1. **[不一致类型]**：[定位 + 原因]
   - 条目：[引用原文]
   - 验证结果：[例如"路径 /x/y/z.ts 不存在（Glob 无匹配）"]
   - 建议：[修正方向]

2. ...

### 处理选项（由主进程决定）
- A) 修正建议条目后重跑本 skill
- B) 显式声明"忽略本条继续"（需主进程记录）
- C) 放弃本次落盘
```

## 阻断策略

**默认阻断**。发现任一不一致即中止返回，不做"自动续跑"也不做"警告继续"。原因：

- 文档一旦落盘即成为未来会话的信息源，错误会级联放大
- 主进程（通常是 retrospective）有完整上下文判断是否值得绕过，本 skill 没有
- 显式的"忽略"动作会留下痕迹，便于后续全量审计追溯

## 记录落点（与 `skill-sync-check` 共享）

主调方若选择"显式忽略本条继续"，**必须**将忽略项归档到项目约定的忽略台账文件（通常是 memory 目录下的 `doc-audit-ignored.md`）。每条格式：

```
[YYYY-MM-DD] [doc] [文件路径] [问题摘要] 理由：[用户陈述]
```

台账在下次 `skill-doc-audit` 全量审计时被读取用于对账：已修复 → 建议移除；仍存在 → 保留并提示复查。

## 与全量审计的区别

| 维度     | 本 skill             | skill-doc-audit |
| -------- | -------------------- | --------------- |
| 触发时机 | 落盘前自动串联       | 用户手动发起    |
| 覆盖范围 | 本次变更圈定的文档   | 项目全部文档    |
| 工具用量 | 轻量，直连           | 可能并行 subagent |
| 输出     | 通过/阻断二选一      | 按文件列修订建议 |
| 作用     | 守门阀               | 体检报告        |

## 如何派生项目定制版

本 skill 是方法论版。具体项目应创建定制版（命名约定：`skill-doc-sync-check-<project>`），分工如下：

| 通用 skill 负责 | 定制 skill 负责                                                             |
| --------------- | --------------------------------------------------------------------------- |
| 核查清单四项    | 本项目**触发范围**的绝对路径（具体 CLAUDE.md / memory 目录）                 |
| 工具选择与反模式 | 本项目**专项检查**（如索引硬性规则、子项目登记规则）                         |
| 输出格式模板    | 与本项目 retrospective 类 skill 的具体衔接（挂哪个阶段、怎么失败反馈）       |
| 阻断策略        | —                                                                           |

**定制 skill 的开头必须声明**：

> 前置：先阅读并遵循 `skill-doc-sync-check`（通用方法论）。本 skill 只列出本项目特有触发范围与专项检查，不重复通用内容。
