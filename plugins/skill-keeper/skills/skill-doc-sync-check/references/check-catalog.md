# skill-doc-sync-check 核查清单与索引完整性强制步骤

本 reference 汇总文档落盘前守门的四项核查以及"索引完整性"这一必做的枚举闭环。`skill-doc-sync-check` 在执行阶段 Read 本文件，按条目逐项做。

---

## 1. 每份文档的四项核查

对输入清单的每份文件执行：

1. **读当前版本**：Read 该文件的当前磁盘内容，标记哪些区域会被改动
2. **未改部分抽样**：对**不打算改动**的条目抽样 3–5 条，验证引用的路径/符号仍有效——若本次未改的旧条目已失效，说明文档已漂移，应提醒用户顺手修
3. **新增/修改条目核验**：对**本次新增/修改**的每一条，逐项验证其引用的路径、函数名、模块、命令在代码库真实存在（Glob / Read / Grep / LSP）
4. **索引联动**：若该文件是索引性质（MEMORY.md、根 CLAUDE.md 索引节、子项目 CLAUDE.md 索引节），按下述「索引完整性强制步骤」做双向差集，不要只抽样

---

## 2. 索引完整性强制步骤（五步闭环，不得降级）

索引完整性漂移是最容易漏报的维度，因为看起来"每条都对"就会判为通过。必须执行：

1. **枚举实际目录**：用 Glob 列出被索引目录下所有候选文件（如 `CLAUDE_DOCS/*.md`、`memory/feedback_*.md`）。得到集合 A
2. **提取索引条目**：Read 索引文件中声明为"该节完整清单"的列表，逐条抽出被引用的相对/绝对路径。得到集合 B
3. **双向差集**：
   - `A − B`：目录有文件但索引未列 → **索引漏登**
   - `B − A`：索引列了但目录无文件 → **存在性失效**
4. **数字核对**：在报告中明确写出 `|A| = N, |B| = M`，差集非空必须列出每一条文件名。不允许只说"索引与目录一致"
5. **子索引登记**：每个子目录的 CLAUDE.md 视为"子索引"，必须在上层（通常根 CLAUDE.md）"子项目指南"节登记；枚举所有子 CLAUDE.md 文件，逐一检查是否出现在上层索引中

**禁止简化**：不得把本闭环降级为"抽样比对"。任何关于索引的"无发现"报告都必须附带 `|A|, |B|` 数字，否则主 agent 退回补做差集。

---

## 3. 工具选择

- 路径存在性 → Glob 或 Read
- 函数/类名 → LSP workspaceSymbol；失败再 Grep 字面
- 符号定义/引用 → LSP goToDefinition / findReferences
- 命令/CLI 可用性 → Read 配置（package.json/pyproject.toml），不真执行
- 索引 vs 目录 → Glob 列目录 + Read 索引逐项比对

**反模式**：`bash grep/rg/find/cat`、裸 `git diff HEAD`。
