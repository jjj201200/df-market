# Backlog 归档流程

本 reference 是 `skill-coding-review` 步骤 5（backlog 归档）的执行手册。每轮 review 结束**必跑**——不允许因"本轮没 backlog"就跳过整理。

---

## 为什么要统一到单一 backlog 文件

simplify 过程中 subagent 经常提出**有价值但不属于本次任务范围**的建议：

- 索引补充建议（性能优化）
- 分层重构建议（service 不依赖 common 之类）
- 命名优化建议（语义对称性）
- 同主题但本次刻意不做的扩展
- 注释 / 文档补充建议
- 与本次 PR 不直接相关的同类隐患

这些项**不能就地丢弃**——一旦本次会话结束就会消失，下次回到同一文件无人提醒。通用做法是统一写入**项目 backlog 文件**（路径由定制版指定，默认 `memory/pending-tasks.md`）。

**硬规则**：不允许新建专题 memory 文件分散归档——单一入口便于检索与提醒。

---

## 5 步整理流程（每次追加前必跑）

`backlog` 文件不是流水账，也不是只读区。**每次要追加任何条目前**，必须对整个文件执行以下整理步骤——不只是 review 分组，而是**全文扫描**。

### 步骤 1. 删除已完成项

逐条核对每个 pending / 进行中条目是否已被某次 commit、PR、用户确认放弃所解决——已解决的**整条删除**，不留"已完成 ✅"尸体。

**验证手段**：

- `git log --oneline` 查近期 commit 是否覆盖该项
- `Read` 验证目标文件是否已是建议状态
- 必要时直接询问用户

### 步骤 2. 去重合并

新条目与已有条目若描述同一件事，**合并到同一条**，"来源"字段追加新轮次；不要保留两条独立记录。

### 步骤 3. 状态推进

剩下未完成的条目，更新状态字段：

- `pending` → `待与用户确认` / `已分流到 plan-X` / `blocked` 等
- 状态描述已过期的**重写**，不要叠加旧状态

### 步骤 4. 重新分组

保持文件按主题分组（通用分组建议）：

- `进行中实施`
- `测试补充`
- `review 累积优化项`
- `架构/重构建议`
- `文档补充`
- `blocked / 待协议讨论`

不让条目按时间散落到错误分组。

### 步骤 5. 空分组清理

某分组所有条目都被删除后，**整个分组标题也删掉**——不要留空分组。

---

## 硬性顺序

**整理 → 追加新项 → 写入**。

- 没整理就追加 = 让 backlog 文件一次比一次乱、一次比一次大、最终没人愿意看
- 整理完成后再追加本轮的"归档 backlog"项（决策表中判定为"归档 backlog"的发现）
- 整理过程要有**可见的输出**（向用户简短报告"清理了 X 条已完成、合并了 Y 条重复、新增 Z 条本次累积"），不要静默改文件

---

## 单条归档格式

```markdown
- **[文件:行号] 问题简述**
  - 建议：xxx
  - 来源：YYYY-MM-DD review 第 N 轮 / agent <类型>
  - 状态：pending / 待与用户确认 / 已分流到 plan-X
```

---

## 自动流程，不征求意见

backlog 的整理 + 写入是硬规则的一部分——**不需要用户批准、不要逐项问"要不要现在处理"**。

每轮 review 结束时：

1. 自动整理 backlog（删已完成 / 合并重复 / 推进状态 / 重新分组）
2. 自动追加本轮新增的"归档 backlog"项
3. 用一段短输出告诉用户"这次清理了 X 条、合并 Y 条、新增 Z 条"——**仅汇报，不征求意见**

---

## push 完成后的总结（强制）

push（或 commit 完成后）主流程必须在结尾输出一段**简短总结**，含：

- 本次提交做了什么（一两行）
- backlog 当前未处理项清单（简短 bullets，不超 10 条）

这段总结是给用户**知情**的，不需要用户对每项做决定。用户看到后若想处理某项会主动开口；不开口就继续积累。

### 模板

```
已 commit/push：<一句话描述>。

backlog 当前积压 N 项（详见 <backlog 文件绝对路径>）：

- [位置] 问题摘要
- ...

如需处理任意一项告诉我。
```

定制版可补充项目 commit 约定、对 push 后总结的具体措辞做本土化调整。

---

## 与其他 skill 的忽略台账的区别

本 skill 的 backlog 是"**有价值但本次不做**"的建设性条目。与以下三者不同：

| 台账 | 内容 | 用途 |
| --- | --- | --- |
| **本 skill 的 backlog** | 本次不做但值得做的建议 | 下次开发同模块时提醒 |
| `skill-subagent-audit` 忽略台账 | subagent 报告被阻断但用户选"B 显式忽略"的条目 | 全量审计时对账 |
| `skill-doc-sync-check` / `skill-sync-check` 忽略台账 | 文档/skill 落盘守门被阻断但用户选"B 显式忽略"的条目 | 全量审计时对账 |

**台账可复用同一物理文件**（项目定制版决定），但**条目前缀必须区分**（如 `[review]` / `[subagent-audit]` / `[doc]` / `[skill]`）。
