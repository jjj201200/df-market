# 文档与代码一致性全量审计（通用方法论）

对项目的全部规范文档、指南手册、外部 memory 做一次系统性体检，识别文档与代码现状之间的漂移，产出可执行的修订建议。本 skill 是**通用方法论**，具体项目应创建定制版 skill 补充本项目的文档拓扑矩阵（见文末「如何派生项目定制版」）。

## 辅助文件

- `references/dimensions.md` —— 5 核查维度 + 索引完整性五步闭环 + 并行 subagent 切分模板 + 工具纪律

执行核查时 Read 该文件；**subagent prompt 必须逐字复述「索引完整性审计的强制步骤」5 步**。

## 核心原则

- **只读审计**：全程使用只读工具（Read/Grep/Glob/LSP），不直接修改任何文件
- **产出建议，不执行落盘**：所有修订动作由用户确认后交给其他 skill（如 memory-refine、skill-doc-sync-check 的定制版）执行
- **优先可扫读的结构化输出**：用表格和分组，不写长段叙述
- **并行切分**：文档数量多时拆给多个 subagent 并行审计，主 agent 只做汇总

## 适用场景

- 周期性文档体检（季度/阶段性节点）
- 怀疑文档漂移（最近重构较多、索引看起来不全、memory 里出现过时陈述）
- 接手陌生项目时建立文档可信度基线
- 大量修改 skill/memory 后的集中验证

**不适用**：改动一两份文档时的快检——那是 `skill-doc-sync-check` 的职责。

## 审计对象的通用分类

大多数由 agent 协作的项目都有下述文档层级，审计时逐层覆盖：

| 层级              | 典型文件                                              | 作用                    |
| ----------------- | ----------------------------------------------------- | ----------------------- |
| 根规范            | `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` / `.cursorrules` | 项目级硬性规则与索引    |
| 手册库            | `CLAUDE_DOCS/`、`docs/`、`documentation/`              | 详细指南手册            |
| 子项目/子模块规范 | 子目录下的 `CLAUDE.md` + 各自手册库                    | 子领域规范              |
| 外部 memory       | `~/.claude/projects/<hash>/memory/`                    | 会话级长期记忆，含索引 `MEMORY.md` |

> **Skill 审计请用 `skill-audit`**。SKILL.md 的核查维度（触发词、description ↔ 正文、职责边界等）与文档审计不同，不在本 skill 范围内。

## 核查维度

5 维度详情见 `references/dimensions.md`。条目摘要：

1. 存在性
2. 符号有效性
3. 索引完整性（**必须跑 5 步闭环，不得抽样**）
4. 描述准确性
5. 状态时效性

## 并行切分

见 `references/dimensions.md` 的「并行切分策略」章节。subagent prompt **必须**明文写入索引强制 5 步，否则子 agent 会自行降级。

## 汇总规则（与 `skill-audit` 统一）

主 agent 汇总 subagent 报告时必须执行：

1. **去重**：按 `(文件路径, 维度, 问题指纹)` 三元组去重；不同 agent 报同一问题只留一条
2. **排序**：硬性规则违反 > 存在性问题 > 索引完整性 > 符号有效性 > 描述准确性 > 状态时效性
3. **二次核验**：主 agent 对 top 5 高优先级建议亲自 Read 原文确认，避免 subagent 误报直接传给用户
4. **证据要求**：每条建议必须附 `文件:行 + 原文引用`，不接受"大概在某处"
5. **索引完整性复核**：对每个 subagent 声称"索引节与目录一致"的报告，主 agent 必须亲自 Glob 一次目标目录并 Read 对应索引节，独立计算差集；若 subagent 未给出 `|A|, |B|` 数字，直接判为报告不合格、重新派发

## 输出格式（通用模板）

主 agent 汇总全部 subagent 报告后，按下述格式输出：

```markdown
## 文档审计结果

### [文档路径]
- **[维度]**：[问题定位] → [建议]
  - 当前内容：[引用现有文本，必要时注明文件:行]
  - 建议修改：[具体修改动作]

### [下一份文档路径]
...

## 无发现的文档
- [路径 1]
- [路径 2]
...

## 高优先级修订建议（按影响度排序）
1. [建议]
2. [建议]
...
```

**建议的优先级排序原则**：

1. 索引完整性破坏（影响未来检索）
2. 存在性问题（引用了不存在的路径/文件）
3. 硬性规则违反（项目规定的强制条款）
4. 符号有效性问题（失效的 API/函数引用）
5. 描述准确性 / 状态时效性（抽样命中）

## 执行约束

- 审计过程禁止修改任何文件——违反即中断
- 输出仅为**建议**，等待用户确认后由其他 skill 执行落盘
- 修订涉及 memory 文件 → 确认后串联 `skill-claude-memory-refine`（如项目配置该 skill）
- 修订涉及 skill 文件 → 用户落盘后必须提醒「⚠️ 修改了 skill 文件，需要重启 Claude Code 才能生效」
- 大规模修订（> 5 份文件）建议分批提交，每批 commit 消息清楚说明"文档审计修订 - 第 N 批"

## 判断标准：何时跳过

- 项目文档 < 5 份 → 逐份人工审计即可，不必调用本 skill
- 最近一周已做过审计且代码无重大重构 → 简述"近期已审计，跳过"
- 用户只想改单个文件 → 走 `skill-doc-sync-check` 流程

## 如何派生项目定制版

本 skill 是方法论版，不绑定任何具体项目的路径。**每个项目应创建自己的定制版 skill**（命名约定：`skill-doc-audit-<project>`），内容分工如下：

| 通用 skill 负责    | 定制 skill 负责                                                         |
| ------------------ | ----------------------------------------------------------------------- |
| 五维度核查标准     | 本项目具体文档拓扑矩阵（绝对路径清单）                                  |
| 工具纪律与反模式   | 本项目的硬性索引规则（如「子项目指南必须登记到根索引」）                |
| 并行切分策略模板   | 本项目规模的具体切分方案（哪个 agent 管哪组）                           |
| 输出格式模板       | 本项目与其他 skill 的衔接点（如 retrospective）                         |

**定制 skill 的开头必须声明**：

> 前置：先阅读并遵循 `skill-doc-audit`（通用方法论）。本 skill 只列出本项目特有拓扑与规则，不重复通用内容。

如此可让通用方法论跨项目复用，各项目只维护自己的拓扑矩阵部分。
