# skill-doc-audit 核查维度手册（6 维度 + 索引强制步骤 + 并行切分）

本 reference 详述 `skill-doc-audit` 的 6 个核查维度、索引完整性的强制闭环、以及并行 subagent 切分模板。主流程执行阶段 Read 本文件，subagent prompt 中必须逐字复述「索引完整性审计的强制步骤」。

---

## 1. 六核查维度表

每份文档至少按下表抽查：

| 维度           | 检查内容                                                               | 工具                                                |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------------- |
| **存在性**     | 文档引用的路径、文件、子目录是否仍在仓库                                | Glob / Read 尝试打开                                 |
| **符号有效性** | 文档提到的函数名、类名、模块名、命令是否仍存在                          | Grep（字面）/ LSP goToDefinition / LSP workspaceSymbol |
| **索引完整性** | 索引条目 ↔ 实际文件的**双向差集**（见下节「强制步骤」，不可降级为抽样） | Glob 列目录 + Read 索引 → 两次集合差集               |
| **描述准确性** | 文档中的一句话描述 / 行为陈述与当前代码行为是否匹配（抽样）             | Read 对照 + LSP hover                                |
| **状态时效性** | project-status、pending-tasks、进度记录类文档所述阶段是否已完成         | Grep 最近 commit message / 代码现状比对              |
| **信号密度**   | 文档每段是否承担明确信号职责；是否存在可删稀释段（见下节「信号密度」） | Read + 段落功能判定                                   |

> **存在性 vs 描述准确性的区分**：若索引/正文引用的目标文件**根本不存在**（Glob 找不到 / Read 失败），必须归为"存在性"问题而非"描述不准"或"路径风格"——因为未来检索会直接 404。subagent 报告时不得用"路径不一致"这类模糊描述替代"文件不存在"。

---

## 1.1 信号密度维度细则

针对文档（CLAUDE.md / AGENTS.md / 手册 / memory），识别"删掉后检索 / 判断不受影响"的稀释段。

**典型稀释形式**（文档场景特有）:

- **索引项过度详述**：MEMORY.md / CLAUDE.md 索引条目应只留 one-line hook，超过约定长度就是稀释
  - MEMORY.md 条目字符上限参考 auto-memory 规范（150 字符）——超限直接标为稀释
- **手册章节内容与上层 CLAUDE.md 重叠 ≥ 70%** → 候选稀释（删正文留指针或反之）
- **memory 文件的"背景叙事"段**：与决策 / 约束无关的历史回溯段

**不算稀释**（按 skill-audit 维度 8 的不算稀释规则通用）:

- 反模式警示、硬规则明确断言、结构承接句一律保留

**方法**：

1. Read 文档全文，按段落切分
2. 每段判断："删掉后影响未来检索 / 决策吗"
3. 答案否定但段落仍存 → 稀释候选
4. 报告必须附 `文件:行 + 首行原文引用`，不允许"某节冗余"

## 2. 索引完整性审计的强制步骤（五步闭环）

索引完整性漂移是最容易漏报的维度，因为看起来"每条都对"就会判为通过。方法论上必须执行下述闭环，不得简化为"抽样比对"：

1. **枚举实际目录**：用 Glob 列出被索引目录下所有候选文件（如 `CLAUDE_DOCS/*.md`、`memory/feedback_*.md`）。得到集合 A
2. **提取索引条目**：Read 索引文件中声明为"该节完整清单"的列表，逐条抽出被引用的相对/绝对路径。得到集合 B
3. **双向差集**：
   - `A − B`：目录有文件但索引未列 → **索引漏登**
   - `B − A`：索引列了但目录无文件 → **存在性失效**
4. **数字核对**：在报告中明确写出 `|A| = N, |B| = M`，差集非空必须列出每一条文件名。不允许只说"索引与目录一致"
5. **子索引登记**：每个子目录的 CLAUDE.md 视为"子索引"，必须在上层（通常根 CLAUDE.md）"子项目指南"节登记；枚举所有子 CLAUDE.md 文件，逐一检查是否出现在上层索引中

**subagent prompt 必须明文写入本节的 5 步**，否则 subagent 会自行把"完整性检查"降级为"抽样"。主 agent 汇总时，任何关于索引的"无发现"报告都必须附带 `|A|, |B|` 数字，否则退回补做差集。

## 3. 并行切分策略（subagent 模板）

审计对象按下述方式切分给并行 subagent：

- Agent 1：根规范 + 根手册库
- Agent 2：所有子项目 CLAUDE.md + 各自手册库
- Agent 3：外部 memory 中的「经验 / feedback 类」文件（通常数量多，独立切一组）
- Agent 4：外部 memory 中的「架构速查 + 项目状态」文件 + MEMORY.md 索引

每个 subagent 的 prompt 必须明确：

1. 要审计的绝对路径清单
2. 五维度核查要点，其中**索引完整性必须逐字复述本文件「2. 索引完整性审计的强制步骤」5 步**
3. 对本组涉及的每个被索引目录，必须先给出 `|A|, |B|` 数字，再列差集
4. 输出格式（见 SKILL.md「输出格式（通用模板）」）
5. 不要 Read 与任务无关的文件，不要修改任何文件
6. 任何"无发现"结论必须附带证据（文件数、差集为空的明证），不得仅凭"看起来对"就判过

## 4. 工具纪律

- **只读**：禁止使用 Write、Edit、Bash 下的修改命令
- **用对工具**：
  - 按文件名找 → Glob
  - 按内容搜 → Grep
  - 查符号定义/引用 → LSP（不要用 Grep 搜函数名）
  - 读文件 → Read（带 offset/limit 只读需要的行）
- **禁止的反模式**：`bash grep/rg/find/cat/head/tail`、`git -C path grep`
- **并行 subagent**：文档数量 > 10 时拆 2–4 组给 Explore 并行审计，主 agent 汇总
- **subagent prompt 只列绝对路径**，让子 agent 自己 Read，避免重复消耗 token

## 5. 机械校验辅助

本 skill 同级提供 `scripts/validate-frontmatter.sh`（共享自 `skill-audit`）用于对**涉及 SKILL.md 审计**的场景做 YAML 合规初筛。对 doc-audit 本身（规范/手册/memory）**无需**用该脚本——它的目标是 SKILL.md，不是一般文档。
